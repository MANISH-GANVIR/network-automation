MPLS - INTERVIEW NOTES
============================================================

MPLS
----

MPLS stands for Multiprotocol Label Switching.
MPLS uses labels instead of routing table lookup.

In traditional IP routing, routers perform a routing table
lookup to determine the next hop for packet forwarding.

MPLS uses labels for packet forwarding, which provides a
scalable and efficient forwarding mechanism widely used
in service-provider and large enterprise networks.

MPLS performs three fundamental operations:

Push → Add the label       → Ingress LER (Label Edge Router)
Swap → Replace the label   → LSR (Label Switch Router)
Pop  → Remove the label    → Egress LER (Label Edge Router)

Benefits / Use Cases:

✅ Efficient and scalable packet forwarding
✅ Can reduce repeated IP lookup processing in the MPLS core
✅ Traffic Engineering (TE) support
✅ QoS support for voice, video, and other traffic
✅ Layer 3 VPN (L3VPN) services
✅ Layer 2 VPN (L2VPN) services
✅ High scalability for service-provider and enterprise backbones

Definition:
MPLS is a packet-forwarding technology that uses labels to
forward packets through the network instead of relying only
on IP routing at every hop.


============================================================
MPLS ABBREVIATIONS
============================================================

MPLS = Multiprotocol Label Switching

LER  = Label Edge Router

LSR  = Label Switch Router

FEC  = Forwarding Equivalence Class

"MPLS stands for Multiprotocol Label Switching. It is a
packet-forwarding technology that uses labels to forward
packets through the network. At the ingress LER, a label is
pushed onto the packet. The LSRs in the core swap the label
and forward the packet, and at the egress LER the label is
popped before forwarding the packet toward the destination."

NETCONF & RESTCONF — INTERVIEW NOTES
====================================

1. WHY DID NETCONF COME INTO THE PICTURE? — HISTORY
----------------------------------------------------

-Earlier, network engineers primarily configured routers and switches manually
 through the CLI.
-Then SNMP (Simple Network Management Protocol) became widely used, mainly for
 monitoring network devices.
-SNMP was later adapted for configuration as well, but configuring devices through
 SNMP had several limitations and challenges.
  (Note:-UDP 161 → SNMP queries/requests & responses (GET, SET, etc.)
  UDP 162 → SNMP Traps/notifications from device to management system)
-The industry needed a better and more structured protocol specifically
 designed for network configuration and management.

This led to NETCONF.
Evolution:

    CLI
      ↓
    SNMP (mainly monitoring, later adapted for configuration)
      ↓
    NETCONF (purpose-built network configuration)
      ↓
    RESTCONF (REST/API-friendly approach)


2. WHAT IS NETCONF?
-------------------
-NETCONF stands for Network Configuration Protocol.
-NETCONF is a protocol used to install, modify, retrieve, and delete configuration
 on network devices programmatically.
-Instead of logging into a router and manually entering CLI commands,
 an automation system can use NETCONF to communicate with the device.

Basic flow:

Management / Automation System
        ↓
     NETCONF
        ↓
       SSH
        ↓
  Network Device


3. HOW DOES NETCONF WORK?
-------------------------

NETCONF uses:

- YANG       -> Data modeling
- XML        -> Data representation / exchange
- SSH        -> Secure transport
- TCP 830    -> Default NETCONF port




4. WHAT IS YANG?
----------------

YANG is a data modeling language used to define the structure of configuration
and operational data.

Think of YANG as a blueprint or schema for network device data.

Example:

Interface
  |
  +-- Name
  +-- IP Address
  +-- Description
  +-- MTU

YANG defines how this information is structured.

Interview line:

"YANG is a data modeling language used by NETCONF and RESTCONF to define the structure of network configuration and operational data."


5. WHY XML IN NETCONF?
----------------------

NETCONF uses XML to represent configuration and operational data.

Instead of sending CLI commands such as:

interface GigabitEthernet0/1
ip address 10.1.1.1 255.255.255.0

the configuration can be represented in a structured XML format.

Remember:

YANG = Data model / structure
XML  = Data representation


6. WHY WAS RESTCONF INTRODUCED?
-------------------------------

As network automation evolved, REST APIs became very popular.

This was driven by:

- Public Cloud
- Private Cloud
- Hybrid Cloud
- Modern automation platforms
- Web applications
- API-based integrations

RESTCONF provides a more RESTful and API-friendly approach to managing YANG-modeled network data.

Think:

NETCONF approach
      ↓
RESTful / API-based approach
      ↓
RESTCONF


7. WHAT IS RESTCONF?
--------------------

RESTCONF is a REST-based protocol used to access and configure YANG-modeled network data.

It uses standard HTTP methods:

GET       -> Retrieve data
POST      -> Create data
PUT/PATCH -> Modify data
DELETE    -> Delete data

RESTCONF commonly uses:

- YANG          -> Data model
- JSON / XML    -> Data representation
- HTTP / HTTPS  -> Transport
- HTTPS TCP 443 -> Common secure port

Basic flow:

Python / Automation Tool
        ↓
   RESTCONF API
        ↓
      HTTPS
        ↓
  Network Device

3. Step-by-Step Explanation
========================================================

Step 1 - User
- User enters www.google.com in the browser.
- Browser needs the server's IP address.

--------------------------------------------------------

Step 2 - Local DNS Cache

Definition:
Stores previously resolved DNS records.

If IP is available:
-> Return IP immediately.

If not:
-> Query Recursive DNS Server.

--------------------------------------------------------

Step 3 - Recursive DNS Server

Definition:
A Recursive DNS Server receives DNS requests from clients and performs
the complete DNS lookup process on behalf of the client.

Usually:
- ISP DNS
- Google DNS (8.8.8.8)
- Cloudflare DNS (1.1.1.1)
- Company Internal DNS

Job:
- Check cache.
- If IP found -> Return IP.
- Otherwise query Root DNS.

--------------------------------------------------------

Step 4 - Root DNS Server

Definition:
The Root DNS Server does not store the IP address.
It only tells the Recursive DNS Server
which TLD DNS Server to contact.

Example:
www.google.com

Root DNS replies:

"I don't know the IP.
Ask the .com TLD DNS Server."

--------------------------------------------------------

Step 5 - TLD DNS Server

Definition:
The Top-Level Domain DNS Server knows which Authoritative DNS Server
manages the requested domain.

Examples:
.com
.net
.org
.in

Reply:
"Ask Google's Authoritative DNS Server."

--------------------------------------------------------

Step 6 - Authoritative DNS Server

Definition:
Stores the actual DNS records for the domain and returns the correct IP address.

Example:

www.google.com
↓
142.xxx.xxx.xxx

--------------------------------------------------------

Step 7 - Browser Connects

After receiving the IP:

- TCP 3-Way Handshake
- TLS Handshake (HTTPS)
- HTTP Request
- Server Response

========================================================

DNS

   Usually the ISP DNS server.

-> Directs the request to the correct TLD DNS Server.

TLD DNS Server
-> Directs the request to the correct Authoritative DNS Server.

Authoritative DNS Server
-> Stores the actual DNS records and returns the correct IP address.

========================================================
5. Common Interview Questions
========================================================

Q. What is DNS?

Answer:
DNS converts domain names into IP addresses.

--------------------------------------------------------

Q. What is a Recursive DNS Server?

Answer:
A Recursive DNS Server receives the client's DNS request and performs
the complete DNS lookup on behalf of the client.
It is usually the ISP DNS server.

--------------------------------------------------------

Q. What is the Root DNS Server?

Answer:
The Root DNS Server directs DNS queries to the appropriate TLD DNS Server.

--------------------------------------------------------

Q. What is a TLD DNS Server?

Answer:
The TLD DNS Server directs DNS queries to the appropriate
Authoritative DNS Server.

--------------------------------------------------------

Q. What is an Authoritative DNS Server?

Answer:
The Authoritative DNS Server stores the actual DNS records
and returns the correct IP address.

--------------------------------------------------------

Q. Why does DNS use UDP?

Answer:
DNS usually uses UDP because DNS queries are small and require
fast responses with low overhead.
TCP is used for zone transfers and large DNS responses.

--------------------------------------------------------

Q. What happens if the Recursive DNS Server already has the record?

Answer:
If the Recursive DNS Server already has a valid cached record,
it immediately returns the IP address without querying the Root,
TLD or Authoritative DNS servers.

========================================================
6. 30-Second Interview Answer
========================================================

When a user enters a domain name, the browser first checks the local
DNS cache. If the record is not found, it sends the request to the
Recursive DNS Server, which is usually the ISP DNS server. If the
recursive server does not have the answer, it queries the Root DNS
Server, which directs it to the appropriate TLD DNS Server. The TLD
DNS Server then points to the Authoritative DNS Server, which returns
the correct IP address. The browser then establishes a TCP connection,
performs the TLS handshake (for HTTPS), and sends the HTTP request.

## 7. MTU
### Interview Answer
MTU (Maximum Transmission Unit) is the maximum packet size that can be transmitted without
fragmentation. Ethernet MTU is typically 1500 bytes.

| MTU                                    | MSS                           |
| -------------------------------------- | ----------------------------- |
| **Layer 3 (Network Layer)**            | **Layer 4 (Transport Layer)** |
| IP Packet Size                         | TCP Payload Size              |
| IP Concept                             | TCP Concept                   |
| Includes IP Header + TCP Header + Data | Only Application Data         |

Application Layer
        │
        ▼
Transport Layer (TCP)
        │
        │  MSS = 1460 Bytes
        ▼
Network Layer (IP)
        │
        │  MTU = 1500 Bytes
        ▼
Data Link Layer (Ethernet)
=========================================================
1. What is MTU?
=========================================================

Interview Answer:

MTU (Maximum Transmission Unit) is the maximum size of an IP packet
that can be transmitted over a network interface without fragmentation.

For Ethernet, the default MTU is 1500 Bytes.

=========================================================
2. Ethernet Frame
=========================================================

| Destination MAC | Source MAC | 802.1Q | EtherType |
                     |
                     V
              IP Packet (MTU = 1500 Bytes)
              --------------------------------
              IP Header (20 Bytes)
              TCP Header (20 Bytes)
              Application Data (1460 Bytes)
              --------------------------------
| FCS (4 Bytes) |

NOTE:
MTU refers only to the IP Packet.
It does NOT include:
- Ethernet Header
- VLAN Tag
- FCS

=========================================================
3. Why is MSS 1460 Bytes?
=========================================================

Ethernet MTU = 1500 Bytes

IP Header   =   20 Bytes
TCP Header  =   20 Bytes
--------------------------
Application Data = 1460 Bytes

Formula:

MSS = MTU - IP Header - TCP Header

MSS = 1500 - 20 - 20

MSS = 1460 Bytes

=========================================================
4. Difference Between MTU and MSS
=========================================================

MTU
- Maximum IP Packet Size
- Layer 3 (IP)
- Includes IP Header + TCP Header + Data

MSS
- Maximum TCP Payload
- Layer 4 (TCP)
- Only Application Data

=========================================================
5. What Happens if Packet Size Exceeds MTU?
=========================================================

Example

MTU = 1500 Bytes

Packet = 2000 Bytes

Case 1:
DF (Don't Fragment) = 0

Router fragments the packet into smaller packets.

Case 2:
DF (Don't Fragment) = 1

Router drops the packet and sends
ICMP "Fragmentation Needed".

=========================================================
6. Why is MTU Important?
=========================================================

- Prevents fragmentation
- Improves performance
- Reduces retransmissions
- Important for VPNs
- Helps efficient packet delivery

=========================================================
7. VPN Interview Question
=========================================================

Q. Why is MTU important in VPN?

Answer:

VPN encapsulation adds extra headers to packets.
If MTU is not adjusted, packets may exceed 1500 bytes,
causing fragmentation or drops.

To avoid this:
- Reduce MTU
OR
- Use MSS Clamping

=========================================================

1) What is a Collision Domain?
-A **collision domain** is a network segment where two or more devices transmitting
 data at the same time may cause a data collision because they share the same
 communication medium.
-A **hub** is a **Layer 1 (Physical Layer)** device.
 It does not maintain a **MAC address table** and cannot identify the source or destination
 MAC address. It simply repeats the incoming signal to all ports.
 Therefore, if multiple devices transmit at the same time, their signals collide,
 making the **entire hub a single collision domain**.

-A **switch** is a **Layer 2 (Data Link Layer)** device.
 It learns and maintains a **MAC address table** by recording the source MAC addresses of
 incoming frames. It then forwards frames only to the correct destination port.
 Since **each switch port is an independent collision domain**, a switch **separates collision
 domains** and prevents collisions in full-duplex communication.

 If the destination MAC address is unknown, the switch floods the frame only within the same VLAN.
 When a host does not know the destination MAC address, it sends an **ARP Request** (broadcast),
 and after receiving the **ARP Reply**, the switch learns and updates its MAC address table.

 ### Example
 Suppose **PC1, PC2, and PC3** are connected to a **hub**. If **PC1** and **PC3** transmit data
 at the same time, their electrical signals share the same communication medium
 and may collide because the hub has no intelligence or MAC address table.

 Now connect the same PCs to a **switch**. "Each switch port is a separate collision domain".
 The switch learns MAC addresses and forwards frames only to the correct destination port,
 so simultaneous transmissions on different ports do not collide.

### Key Interview Points
    * **Hub = Single Collision Domain**
    * **Switch = Separates Collision Domains (Each Port = One Collision Domain)**
    * **Router = Separates Broadcast Domains**
    * **VLAN = Each VLAN can also creates its own separate Broadcast Domain**

### One-Line Interview Summary

> **Hub creates a single collision domain because it simply repeats signals.
> A switch separates collision domains by forwarding frames based on its MAC address table.
> A router separates broadcast domains, and each VLAN also forms its own broadcast domain.**


2)What is a Broadcast Domain?
- "A broadcast domain is a network segment where a broadcast frame
  (Destination MAC: FF:FF:FF:FF:FF:FF) is received by all devices in the same network.
  A switch forwards broadcast traffic to all ports within the same VLAN.
  A router does not forward broadcast traffic to another network,
  so it separates broadcast domains. Similarly, each VLAN creates its own broadcast domain."

Example:-
 -Suppose PC1, PC2, and PC3 are connected to the same switch.
  If PC1 sends an ARP Request, the switch forwards that broadcast to all devices
  in the same VLAN. If there is a router connecting another network,
  the router will not forward that broadcast to the other network.
  That's why routers separate broadcast domains."

One-line summary
    Hub = 1 Broadcast Domain
    Switch = 1 Broadcast Domain by default
    Each VLAN = 1 Separate Broadcast Domain
    Router = Separates Broadcast Domains

Switch + VLANs	        Each Port = 1	                                   Each VLAN = 1
Router	                Each Interface = Separate Collision Domain	       Each Interface = Separate Broadcast Domain

FCS / CRC (Frame Check Sequence)
--------------------------------
FCS (Frame Check Sequence), also called CRC (Cyclic Redundancy Check), is the
last field of the Ethernet frame and is 4 Bytes long.

Purpose:
- Detects transmission errors in the Ethernet frame.
- The sender calculates the CRC value and stores it in the FCS field.
- The receiver recalculates the CRC.
- If both values match, the frame is accepted.
- If they do not match, the frame is discarded.

Interview Answer
----------------
FCS (Frame Check Sequence) is a 4-byte field at the end of the Ethernet frame.
It uses the CRC algorithm to detect transmission errors. If the calculated CRC
at the receiver matches the received FCS, the frame is accepted; otherwise, it
is discarded.

Router-on-a-Stick (ROAS) - Interview Notes
=========================================

1. What is Router-on-a-Stick?

Answer:
Router-on-a-Stick (ROAS) is an inter-VLAN routing technique in which a single
physical router interface is configured as an IEEE 802.1Q trunk. Multiple
subinterfaces are created on the router, and each subinterface is assigned
to a different VLAN with its own IP address. This allows communication
between different VLANs using a single physical router interface.

------------------------------------------------------------

2. Why is it called Router-on-a-Stick?

Answer:
It is called Router-on-a-Stick because a single physical router interface
acts as a trunk ("stick") and carries traffic for multiple VLANs using
multiple logical subinterfaces.

------------------------------------------------------------

3. Why do we need Router-on-a-Stick?

Answer:
Devices in different VLANs cannot communicate directly because each VLAN is
a separate broadcast domain. Router-on-a-Stick provides Layer 3 routing
between VLANs, enabling inter-VLAN communication.

CI stands for Continuous Integration,
and CD stands for Continuous Delivery or Continuous Deployment.

CI/CD automates the process of integrating code,
testing, building, and deploying software.

In our environment, we use a CI/CD pipeline based on
Git, GitHub, GitHub Actions, Docker, Docker Hub, and Azure VM.

Git is a version control system used to track code changes.
Developers write Python code in the local repository and then
use Git commands such as add, commit, and push to send the code
to the GitHub repository, which stores and shares the source code remotely.

Once the code is pushed to GitHub, a webhook event automatically
triggers the GitHub Actions workflow.

A webhook is an event notification mechanism. When a specific event occurs,
it automatically notifies another application.

The Docker image is pushed to Docker Hub, which acts as a container registry.

From there, the target server, which is an Azure VM,
pulls the latest Docker image.
